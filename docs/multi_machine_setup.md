# 多机部署指南

调度器支持多台机器分担任务执行，各机器共用同一个数据库，通过 HTTP API 实现跨机器任务触发。

## 一、部署架构

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   机器 A     │     │   机器 B     │     │   机器 C     │
│ :8000       │     │ :8000       │     │ :8000       │
│ 调度器+执行  │     │ 调度器+执行  │     │ 调度器+执行  │
└──────┬──────┘     └──────┬──────┘     └──────┬──────┘
       │                   │                   │
       └───────────────────┼───────────────────┘
                           │
                    ┌──────┴──────┐
                    │   MySQL     │
                    │  共享数据库   │
                    └─────────────┘
```

- 每台机器独立运行调度器和 Web 服务
- 所有机器共用同一个 MySQL 数据库
- 各机器通过局域网 HTTP API 互相触发任务

***

## 二、每台机器独立部署

每台机器重复 [README 首次部署](../README.md#一首次部署) 步骤，确保：

### 2.1 环境要求

- 各机器需在同一局域网且能互相访问端口 8000（如果端口占用请统一修改为其他端口）
- 各机器共用同一个 `.env` 中的数据库配置

### 2.2 配置要点

| 配置项                  | 说明                  |
| -------------------- | ------------------- |
| `SCHEDULER_API_PORT` | 保持 `8000`（确保未被占用）   |
| 数据库配置                | 所有机器指向同一个 MySQL 数据库 |

### 2.3 代码同步

使用 `deploy.bat `从 Gitea 拉取最新代码，确保各机器代码版本一致：

```PowerShell
.\deploy.bat
```

## 三、配置执行机器

在管理后台「任务调度 → 执行机器」中录入各机器的局域网 IP。

| 字段    | 说明                      |
| ----- | ----------------------- |
| 名称    | 机器标识（如：开发机、生产机A）        |
| IP 地址 | 局域网 IP（如：192.168.1.100） |
| 端口    | API 端口，默认 8000          |

***

## 四、分配任务到机器

编辑任务时「分配机器」字段选择目标机器：

| 配置方式     | 行为                      |
| -------- | ----------------------- |
| **留空**   | 所有机器均可执行                |
| **指定机器** | 仅选中机器执行（定时调度 + 手动触发均生效） |

### 4.1 立即执行

「立即执行选中任务」会向所有分配机器发送代理执行请求。

***

## 五、跨机执行原理

```
机器A（发起）  ──HTTP POST──▶  机器B（执行）
                                 └─ /api/tasks/<id>/execute/
```

调度器自动判断：

- 当前机器在分配列表 → 本地执行
- 当前机器不在分配列表 → 向目标机器的 API 端点发送 HTTP 请求

***

## 六、注意事项

### 6.1 端口冲突

确保每台机器端口 8000 未被占用，或修改其他端口。

### 6.2 防火墙

各机器需开放对应端口的入站规则（以8000为例）：

```powershell
netsh advfirewall firewall add rule name="Django APScheduler" dir=in action=allow protocol=tcp localport=8000
```

### 6.3 数据库连接

- 所有机器使用相同的数据库配置
- 确保各机器能访问数据库服务器
- 首次部署，需要在第一台机器执行 `python manage.py migrate` 初始化数据库，后续其他机器不需要再执行

### 6.4 任务同步

- 任务配置存储在数据库中，所有机器共享
- 修改任务后无需重启，各机器会自动同步
- 代码更新后需在各机器执行 `restart_service.bat` 重启服务
